What happens to selected files?

FileForge reads the files you select into browser memory and processes them on your device. The website has no file-upload endpoint, online file storage, account system or conversion history. Your source files are not changed.

You choose whether to download the result. Clearing a selection releases the tool’s references, previews and result link. Leaving or closing the page ends its current work. Your browser and operating system manage memory cleanup; this is not a promise of secure memory erasure.

Your browser may cache website code, fonts and conversion engines. FileForge does not use that cache to save your selected files or results.

What can be saved on this device?

The Image studio has an optional “Remember my image settings” checkbox. If selected, it stores only output format, quality, maximum width and a settings version in your browser’s local storage, under fileforge:image-settings:v1.

No filenames or file contents are included. Uncheck the option in Image studio to remove those settings, or clear this site’s data in your browser. The website does not set analytics or advertising cookies.

The idea machine and feedback form keep what you type in the current page only. Feedback leaves the site only when you choose to continue to GitHub.

What about ordinary website visits?

GitHub Pages hosts this website. Loading a page sends ordinary network requests to the host, including your IP address. GitHub states that it logs visitor IP addresses for security purposes. This is separate from the contents of files you select inside FileForge.

Cloudflare provides the domain and DNS service. DNS is the lookup that helps a browser find the website; it is not where FileForge conversions run.

Read GitHub Pages’ data collection note, the GitHub privacy statement and Cloudflare’s privacy policy for those services’ own practices.

Links, downloads and feedback

Source code, desktop downloads and issue reporting link to GitHub. Opening those links uses GitHub’s service under its own policies. Submitting an issue in a public repository makes that report public; don’t include private documents, passwords or personal information.

The contact page can prepare an issue draft locally. It does not submit or publish anything for you. You review and submit on GitHub.

This page describes the website and browser tools. Desktop apps have their own behaviour, including local working files. See the FileForge desktop documentation and Repodock documentation before installing.
